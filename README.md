# Платформа подбора ИТ-специалистов ФСП

Цифровая платформа-агрегатор ИТ-вакансий с верифицированным профилем достижений
участников Федерации спортивного программирования (ФСП).
Хакатон «Лидеры цифровой трансформации 2026» · специальный трек ФСП · команда **VOLTRON PRIME**.

Платформа работает с **обратной механикой** (модель LHH): кандидат проходит опрос и
тест, получает категорию (специализация + подтверждённый грейд), а работодатель сам
находит нужную категорию и направляет **адресное приглашение** конкретному человеку
с обязательной зарплатной вилкой. Достижения ФСП подтверждаются и дают буст
ранжирования внутри категории, но не заменяют тест.

---

## Возможности

**Кабинет кандидата**
- Профиль: заполнение формы, загрузка PDF-резюме с авторознаванием (ФИО, контакты,
  стек, стаж, софт-скиллы), автогенерация стандартизированного PDF-профиля.
- Опрос → выбор грейда → тест: у каждого кандидата уникальный набор заданий из банка
  с выравненной сложностью; code-задачи проверяются прогоном в Docker-песочнице,
  открытые ответы — ИИ по рубрике с экспертной перепроверкой.
- Категория и грейд: история тестов, тест на грейд ниже/выше, кулдаун смены грейда 90 дней.
- Приглашения от работодателей с вилкой зарплаты: принять / отклонить.
- Вакансии и отклики (дополнительный сценарий): отклик, отзыв, повторный отклик.
- Регулярные короткие задания от работодателей: решить задачу или предложить подход.
- Настройки: приватность профиля, согласия (152-ФЗ), привязка ID участника ФСП.

**Кабинет работодателя**
- Профиль компании, описание потребности → формирование подборки.
- Подборка кандидатов: сохранённый снапшот с ранжированием, чипы критериев,
  уточнение фильтров без потери подборки, объяснение каждой позиции.
- Поиск по банку: фильтры по специализации, грейду, категории, стеку, городу,
  наличию достижений ФСП; история запросов с восстановлением фильтров.
- Адресное приглашение: описание + обязательная вилка + компания + способ связи;
  контакты кандидата раскрываются после принятия приглашения или отклика (аудит).
- Вакансии и работа с откликами, короткие задания кандидатам с оценкой ответов.
- Концепция ATS-интеграции (конфигурация, маппинг полей, точка расширения).

**Общее**: уведомления о событиях, ролевая модель (кандидат / работодатель /
администратор), Swagger UI, мобильная адаптация интерфейса.

## Быстрый старт (Docker Compose)

Требования: Docker с Compose-плагином, доступ в сеть (образы песочницы).

```bash
# 1. Секреты и настройки
cp .env.example .env
#   заполните .env: минимум JWT_KEY (длинная случайная строка) и POSTGRES_PASSWORD

# 2. Образы для code-раннера (один раз)
docker compose --profile runner pull

# 3. Сборка и запуск
docker compose up --build

```

Открыть:
- Веб: http://localhost:3000
- API + Swagger: http://localhost:8080/swagger
- Почта (подтверждения регистрации): http://localhost:1080

&gt; На Linux вместо `//var/run/docker.sock` в `docker-compose.yml` используйте
&gt; `/var/run/docker.sock` (песочнице кода нужен доступ к Docker-демону).

### Демо-аккаунты (пароль у всех: `password123`)

| Роль          | Аккаунт |
|---------------|---------|
| Администратор | `admin@demo.ru` (активация банка вопросов через Swagger) |
| Работодатель  | `hr@techsphere.demo.ru` (компания «ТехноСфера»), `hr@severdata.demo.ru` |
| Кандидаты     | `candidate1@demo.ru` … `candidate17@demo.ru` (разные специализации и грейды, с/без истории ФСП, candidate16–17 — «грейд не подтверждён») |

### Сквозной сценарий (3–5 минут)

1. Регистрация кандидата (письмо с подтверждением — в Maildev) → опрос → тест → категория.
2. Регистрация работодателя → профиль компании → «Кого ищем» → подборка.
3. «Пригласить» у кандидата из подборки → вилка обязательна → кандидат принимает.
4. Карточка кандидата → контакты открылись (аудит записал).
5. Дополнительно: отклик на вакансию, короткое задание, загрузка PDF-резюме.

Образцы резюме для проверки распознавания PDF (ТЗ 2.1):
`demo-data/resumes/resume_kim_ds.pdf`, `demo-data/resumes/resume_orlov_qa.pdf` —
кабинет кандидата → «Профиль» → «Резюме (PDF)» → «Выбрать файл».

## Локальная разработка (без Docker)

- **БД**: PostgreSQL 15+, строка подключения — `FspPlatformApi/appsettings.json`
  (`ConnectionStrings:Default`).
- **Backend**: `cd FspPlatformApi && dotnet restore && dotnet run`
  (миграции применяются при старте; Swagger — `/swagger`).
- **Frontend**: `cd FspPlatformWeb && npm install && npm run dev` → http://localhost:5173
  (адрес API — `VITE_API_URL`, по умолчанию `/api`; CORS — список `Cors:Origins`).
- **Демо-данные**: `psql -d fsp_platform -f demo-data/sql/seed-questions.sql` затем
  `psql -d fsp_platform -f demo-data/sql/seed-demo.sql` (порядок важен).

## API

Все методы документированы в OpenAPI (Swagger UI по адресу `/swagger`):
запросы, ответы, коды ошибок, JWT Bearer. Краткая сводка групп эндпоинтов —
в документации, раздел 7.

## Безопасность и ПДн

- Пароли — BCrypt, токены подтверждения почты — SHA-256, JWT с валидацией issuer/audience.
- Ролевая модель на уровне контроллеров; контакты кандидата скрыты до принятия
  приглашения или отклика (ТЗ 2.2); каждое раскрытие контактов пишется в аудит.
- Журнал согласий (152-ФЗ): согласие на обработку и публикацию данных профиля —
  в настройках кабинета. Через LLM проходят только служебные тексты (без ПДн),
  провайдер в российской юрисдикции.
- Флаг `verified` у достижений ФСП может ставить только реестр (коэффициент 1.5).
